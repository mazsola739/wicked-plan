# Wicked Plan — brief for the coding agent

Wicked Plan is a **puzzle and party-game web page** in the genre of The Devil's Plan: one page lists
every game (`docs/games.md`); pick one and play it. Solo puzzles are played alone; games for several
players are played against **bots** in the browser. Rooms with friends and a server may come later.

The page is for **both desktop and phone**: a desktop browser with mouse and keyboard, and a portrait
phone held in one hand. Every action works by click/touch; the keyboard adds shortcuts (never the only
way), and hover only adds highlights.

**Everything in the product and the repo is English** (UI, docs, code, commits).
Chat with the user in Hungarian.

## Source documents

- **`docs/design.md`: the main plan**: decisions, milestones, open questions.
- **`docs/games.md`: the game catalogue** (51 games, by type), with what is done.
- `docs/games/<game-id>.md`: one rules page per game; the page is the spec, write it first.
- `docs/dev.md`: dev tools (tunnel, pre-commit, Biome, agents).
- `Wicked Plan 1 - Design Plan.pdf`: the source of the catalogue.

When a rule or number changes, change it in the docs first, then the code.

## Stack (versions are pinned; don't bump without a reason)

| Layer | Tool |
|---|---|
| Page | React 19 + TypeScript 7, Vite 8, single page (`apps/web`) |
| Rules | Rust 2024 crate `crates/rules`, built to WebAssembly by `crates/wasm` (wasm-bindgen 0.2.106) |
| Tests | `cargo test` (rules and the wasm bridge) |
| Lint / format | Biome 2 (TS), rustfmt + clippy (Rust) |
| JS runtime | Bun 1.4: packages (`bun.lock`), workspaces, scripts; runs Vite, tsc and Biome (no Node needed) |

## Layout

```

  GameIcon.tsx          each game's neon icon (the user's art, assets/icons/<game-id>.webp)

  games/<Name>.tsx      one screen per game (default export, props: ScreenProps)
  games/common.tsx      shared UI: Play layout, TimerBar, GameTop, RoundDots, NumberPad, useKeys, KeyHint, nameOf, move
  games/QuizGames.tsx, BoardGames.tsx   the six first games
  wasm/                 generated by `bun run wasm` (git-ignored)
crates/
  rules/src/game.rs     the Game contract, Session, bots (with_bots), rank_by_score, test helpers
  rules/src/lib.rs      registry!(…) of every game module, new_table (you + bots)

  wasm/                 LocalGame for the browser

```

## Commands (run from the repo root)

```
bun install            # packages (once after a clone, and after a dependency change)
bun run dev            # builds the wasm, then the page on 5173
bun run wasm           # rebuild the rules for the browser after a Rust change
bun run test           # cargo test: rules and wasm bridge (not `bun test`)
bun run typecheck      # the page (needs `bun run wasm` once)
bun run lint           # Biome lint (format: bun run format; the pre-commit formats staged files)
bun run build          # production build of the page (static files)
bun run tunnel         # public HTTPS link to the dev server (phone off the Wi-Fi, friends)
bun run map <folder>   # one line per file with its exports; cheaper than opening files
bun run hooks          # turn on the pre-commit checks once per clone
```

## How to work

- **Think first.** Say the assumption you build on in one line. If a request reads two ways and the
  readings give different results, ask when it is gameplay, rules or player experience; for a
  technical choice pick one and say which.
- **Keep it simple.** The least code that solves the request: no speculative options or
  abstractions for a single use.
- **Change surgically.** Every changed line traces back to the request; match the style around it.
- **Work to a check.** A bug gets a failing test first where the area has tests; a screen change
  gets a look in the preview at desktop and phone size. Done means the check passes.
- **Never skip the pre-commit hook** (`--no-verify`); fix what it reports.

## Golden rules

1. **Secrets stay in the state.** Hidden cards, roles and secret numbers live only in the rules'
   `State`; a seat gets only its `view_for`. The page shows only the view of seat `"you"`, so a
   server can referee later without changes.
2. **Every game implements `Game`** (`crates/rules/src/game.rs`) as `pub struct Rules` (or
   `pub type Rules`) with `pub const READY: bool = true`, in its own module. The page and bots only
   talk to that contract.
3. **Rules are pure and seeded.** Use `Rng::new(seed)`; no clock, no other randomness. Time arrives
   through `tick`. Same seed = same game.
4. **Every rules module ships with tests and a bot**, including the "1,000 random bot games:
   nothing crashes, every game ends" test (`testing::bot_games` for solo, `testing::bot_games_with`
   for several seats). Puzzle games get a generator + solver first. Bots play sensibly, not randomly.
5. **Original branding only.** The games follow the show's genre and mechanics, but names, art,
   texts and look are our own. No names, logos, music or footage from TV shows or other games;
   the one exception is the credit line under the picker title ("Based on the idea of the show …").

## Adding a game

Every game already has its own files (stubs). Replace only these, never shared files:

1. `docs/games/<id>.md` — the rules page: first a `## How to play` section for players (a **Goal:** line
   and short bullets; only paragraphs, `- ` bullets and `**bold**`), shown in the game by `HowTo.tsx`;
   then `## Rules in detail`, the spec: seats, rounds, timers, scoring, moves, view, bot, and a
   **Replay moments** line (the game's big moments, rare, never revealing a secret). A timer only
   where the game's line in `docs/games.md` gives a time limit or a race; otherwise a phase ends
   when everyone has moved.
2. `crates/rules/src/games/<id_snake>.rs` — replace the `stub_game!` line with the real rules:
   `pub const READY: bool = true;`, `pub struct Rules;` implementing `Game` with the same `info()`
   id/kind/min/max as the stub (name and `short` may be improved). Several seats: implement `to_move`
   (whose move it is; for secret simultaneous bids, everyone who has not bid yet); results via
   `rank_by_score`. `GameInfo` also needs a `difficulty` and 1-3 `tags` (docs/games.md,
   Categories). Replay moments: a `moments: Moments` in the state, pushed where they happen, and
   `fn moments` (see `minus_one.rs`), with a test that one fires and a `moment_stats` test that
   they stay rare. Tests in the same file.
3. `apps/web/src/games/<PascalName>.tsx` — the screen (default export, `ScreenProps`); cast
   `view` to a view type declared in the same file. Use `Play`/`GameTop`/`TimerBar` and `move()`
   from `common.tsx`, `nameOf(id)` for seat names ("you", "bot-1"…). Game-specific CSS goes in
   `apps/web/src/games/<PascalName>.css`, imported by the screen, class names prefixed with the id.
4. `bun run test`, `bun run wasm`, `bun run typecheck`, `bun run lint`; play it in the preview.

Seats on the page: `GameInfo::seats()` (the minimum, or 4 when allowed, never above the maximum);
seat 0 is `"you"`, the rest are bots that move by themselves when `to_move` lists them.

## Page rules

- Desktop from 720 px (wider page, board beside the controls via `Play` in `games/common.tsx`) and
  phone from 360 px are both checked in the preview.
- Desktop keys go through `useKeys`; show them with `KeyHint` (visible only with a real mouse and keyboard).
- Touch targets ≥ 48 css px. Main actions in the lower half on a phone.
- Everything ships with the page: fonts and art are bundled (or drawn in SVG/CSS), no CDN at runtime.

## Working agreement

- "Done" means the check in the milestone table, verified.
- Run the tests yourself before saying a game works.
- Commit only when the user asks.

## Known gotchas

- `bun test` is Bun's own test runner, not the `test` script: the Rust tests run with `bun run test`.
- `bun run typecheck` needs `apps/web/src/wasm/` (run `bun run wasm` once after a clone).
- The wasm-bindgen CLI must match the crate version exactly (0.2.106):
  `cargo install wasm-bindgen-cli --version 0.2.106 --locked`, and `rustup target add wasm32-unknown-unknown`.
- Windows PowerShell 5.1 reads UTF-8 files without a BOM as the ANSI code page (1250 here) and
  `Set-Content -Encoding utf8` adds a BOM: never rewrite source files with Get-Content/Set-Content;
  use the Edit tool or a Bun script.
